# Tempest 2000 for Apple TV (tvOS)

A native tvOS app: the same original `t2000.abs` running on the Virtual Jaguar core (linked in statically),
with a small UIKit front end (`T2KTV/main.m`). No SDL needed.

## Install on an Apple TV (side-loading with Xcode)

1. One-off: install the tvOS platform component (Xcode's asset compiler needs it to build the icon):
   `xcodebuild -downloadPlatform tvOS`   (or Xcode > Settings > Components > tvOS)
2. Pair the Apple TV: on the TV open Settings > Remotes and Devices > Remote App and Devices; on the Mac
   open Xcode > Window > Devices and Simulators, pick the Apple TV and enter the code it shows.
3. `open Tempest2000TV.xcodeproj`, select the *Tempest2000TV* target > Signing & Capabilities, choose your
   team (already set to your Personal Team; change the bundle id if Xcode says it is taken), pick your
   Apple TV as the run destination and press Run.

With a free Apple ID the app expires after 7 days; re-run from Xcode to renew it.

## Rebuilding

* `./build_core.sh`  rebuilds `libvjcore_dev.a` / `libvjcore_sim.a` from `../third_party`.
* `python3 make_tv_assets.py` regenerates the icon and top shelf images.
* `python3 gen_xcodeproj.py [TEAM_ID] [BUNDLE_ID]` regenerates the Xcode project.
* `T2KTV/t2000.abs` is a copy of `../t2000.abs`.

## Performance notes

Profiling on an Apple TV 4K showed the accurate blitter (`BlitterMidsummer2`) taking 61% of emulation time and
causing frame drops in blitter-heavy scenes. The app therefore selects the core's *Fast* blitter
(`virtualjaguar_usefastblitter`), which brings every scene well under the 16.7 ms frame budget with no audio
underruns; Tempest 2000 looks the same. Emulation runs on its own thread; `bench.sh` prints per-600-frame timings.

A second profile showed the DSP interpreter at ~46% once the blitter was fixed, mostly `dsp_opcode_jr` spinning in wait
loops. The core's *RISC idle-loop fast-forward* skips those loops; the core only enables it when the frontend asks for
it, so the app now does. It is bit-exact (identical frame and audio hashes over 3000-4000 frames, checked with
`t2k_host --test-frames N`), cut the DSP from ~46% to ~15% of emulation time, and left the blitter (~48%) as the remaining hot spot.

## Blitter specialisation

With the fast blitter selected, `blitter_generic` was still ~48% of emulation time: one loop that decoded the blit
mode per pixel. Tempest 2000 only ever issues 14 distinct blit command words (4 cover 94% of pixels), so
`third_party/virtualjaguar-libretro/src/tom/blitter.c` now compiles a copy of the same loop for each hot command word
with the command as a constant (the mode tests fold away), and adds a direct constant-fill path for screen clears
(`blitter_fill_line`, ~60% of all blitted pixels). Results are bit-identical: `../regress.sh` compares video, audio and
full-state hashes over four scripted play-throughs against the unmodified core. Blitter share on the Apple TV: 48% -> ~14%.
After rebuilding the core (`./build_core.sh`) run `../regress.sh` (needs `make t2k_host` in `..`).

## Icon

The app icon and top shelf images are generated by `make_tv_assets.py` from `icon_source.jpg` (the Tempest 2000 title logo): the logo (black keyed to transparent) sits on the front layer, over a generated starfield, for the tvOS parallax effect.
